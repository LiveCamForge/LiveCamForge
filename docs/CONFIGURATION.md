# Configuration Reference

## Configuration layers

LiveCamForge uses three configuration layers:

1. `config/app.php` — distributed defaults. Do not edit this file for host-specific settings because upgrades replace it.
2. `config/local.php` — private host-specific configuration, credentials and security boundaries.
3. Admin operational settings — database-backed settings managed from the administrator interface.

The effective order is distributed defaults → local configuration → permitted Admin overrides.

Sensitive values such as database credentials, provider keys, affiliate codes, validation salts and postback secrets remain in `config/local.php`. Admin can update supported provider credentials, but the values are still persisted to the private local file.

## Local configuration

`config/local.php` returns a PHP array:

```php
<?php

declare(strict_types=1);

return [
    // host-specific values
];
```

Use `config/local.example.php` as the reference shape for a manual installation or troubleshooting comparison.

## Site identity and URL

The public/base URL should match the canonical HTTPS URL used in production. Incorrect base URLs can affect generated links, canonical tags, postback URLs and deployment checks.

## Public Demo mode

`demo_mode.enabled` is a distributed configuration flag that defaults to `false`. The supported way to create a Public Demo is to select **Install as public demo** during a clean installation.

Do not repurpose a Public Demo as a live site by toggling the flag later. Production should use a separate standard installation. See [Public Demo mode](PUBLIC_DEMO.md).

## Locales

Public languages are selected from installed language packs. A fallback locale is used whenever public editorial content or interface text is missing in the requested locale. See [TRANSLATIONS.md](TRANSLATIONS.md).

## Provider credentials

Provider credentials and affiliate-network credentials should normally be configured from Admin → Integrations. Provider-specific guides document the exact fields and supported capabilities.

## Catalog configuration

Catalog source selection is managed from Admin → Public Catalog. A commercial brand that can be supplied both directly and through an affiliate network has one active public source at a time, preventing duplicate performer inventory.

## Secrets

Never commit `config/local.php` or paste production secrets into issue reports. Rotate credentials if they have been exposed. Postback endpoints should use strong independent secrets.

## Database performance recommendations

For larger combined catalogs, LiveCamForge reports advisory checks for:

- `innodb_buffer_pool_size` — recommended 64 MiB or higher;
- `max_allowed_packet` — recommended 8 MiB or higher.

The application uses a conservative DB sync batch of 200. Optional CLI diagnostic overrides are intentionally bounded to avoid oversized SQL packets.

## Advanced diagnostics

Public request profiling can be enabled only in a safe diagnostic context using `?perf=1`.

For provider synchronization, **Admin → Operations** provides the normal operational status and sync history required for day-to-day administration. If shell/SSH access is available, additional low-level timing diagnostics can optionally be collected with:

```bash
php bin/sync.php stripchat --profile
```

CLI profiling is intended for troubleshooting and performance analysis and is not required for normal shared-hosting operation. Do not expose diagnostic output unnecessarily on a public production site.
